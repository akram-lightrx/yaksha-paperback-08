# Asura Scans Paperback 0.8 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add an independently installable Asura Scans source to the existing Paperback 0.8 repository.
**Architecture:** Retain Yaksha unchanged. Adapt Nicartjay's public API search, Astro page data and image tile mapping to the official 0.8.7 Source/App interfaces. Use native PBImage/PBCanvas for image reconstruction.
**Tech Stack:** TypeScript, @paperback/types and toolchain 0.8.7, existing Node tests, GitHub Actions.
**Spec:** The user's request "make one for asurascan", with earlier autonomy, compilation, live testing and GitHub publication requirements.

## Constraints and decisions
- AsuraScans is a separate source, sharing the existing installation URL.
- Target https://asurascans.com and its public API https://api.asurascans.com/api.
- Preserve Yaksha source, fixtures and IDs.
- Public chapters only; hide locked/premium/active early-access chapters. No account or payment access.
- Keep Nicartjay's MIT notice and attribution.
- No browser-global dependencies in the compiled source.
- Native iPhone rendering is a final user check.
- Local execution environment is unavailable. Use an isolated GitHub branch and Actions for compilation, tests and live requests. No deployment until validation passes.
- User previously opted out of planning questions; implementation choices are delegated.

## Review focus
- Astro typed arrays must retain all pages, including two-page chapters.
- Unrelated/malformed Astro islands must not hide the correct payload.
- Premium and timed early-access chapters must not be offered as readable.
- Image tile permutation must map source tiles to destination positions, preserve order, reject invalid maps and avoid returning scrambled bytes silently.
- Failed HTTP/JSON/challenge pages must not become empty search results.
